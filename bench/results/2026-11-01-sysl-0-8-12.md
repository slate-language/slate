# slate 0.1.34: sysl 0.8.12, and a new object that allocates no index

Every binary is a PGO build from `bench/pgo.sh`, and each comparison is `bench/alternate.pl 5`: the two
binaries run alternately, program by program, and the lowest of five rounds is kept. Times are
milliseconds, all taken under `caffeinate`.

Two changes, measured one at a time:

- **sysl 0.8.12** stops re-reading a `Buf` handle held in a struct field after each count write. The
  source is 0.1.33's. Idle was 51% at the start of the first comparison and 90% at the end.
- **`5dab60c`** leaves a new object's index as the allocator handed it. An empty `buf()` allocates a
  core of its own, so every object built paid for an index it never used. The heap's reserve is the
  one block that is not fresh, so a non-empty index there is still cleared. Measured at 94% idle.

`sorting` is still the one program faster than 0.1.8 (-11.1%), and `alloc` went from +51% to +11.9%.
sysl's analysis puts most of the remaining gap in its boxed `Buf` handle (8 to 46 handle dereferences per
unit of work), which is input to sysl's 0.10.0 memory model rather than a patch.
