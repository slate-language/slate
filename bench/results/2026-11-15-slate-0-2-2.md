# slate 0.2.2 on sysl 0.11.2, against the seven yardsticks

The binary is a `bench/pgo.sh` build of `4006cc2` (tag v0.2.2, sysl 0.11.2). `bench/check.sh` came first,
and every twin gave the same answers as before. The timing was `bench/run.sh -n 5`, which takes the best of
five wall times in milliseconds. It ran as a `marshal run --exclusive --quiet-load auto` job, so it started
only after marshal had drained and the load from outside marshal had settled.

Idle was 92.9% before the run and 90.7% after it. The 30-second load samples mostly show WindowServer at
about 30% as the busiest outside process. Two samples were busier:

- at the start of the run, `mediaanalysisd` was at 118% and an `avin` process at 100%;
- one sample in the middle showed two Chrome renderers at 89% and 51%.

The yardsticks' own times read 1–5% slower than in the 0.11.0 run; Lua's `fib`, for example, went from
81.4 to 85.3 ms. Read slate's column with that in mind.

## What moved

Compared with the 0.11.0 table, slate's own column:

- **`funcs` 101.2 → 115.6 ms (+14%) and `globals` 55.7 → 62.7 ms (+13%).** Lua's times for both stayed
  flat, so these were checked by counting. Each was run under `/usr/bin/time -l`, against both this
  binary and the 0.11.0 binary kept from that run:

  | program | instructions, 0.11.0 → 0.2.2 | cycles, 0.11.0 → 0.2.2 |
  |---|---:|---:|
  | `funcs` | 3.221G → 3.218G | 496M → 524M (+5.5%) |
  | `globals` | 2.159G → 2.176G (+0.8%) | 247M → 261M (+5.6%) |
  | `branches` | 4.499G → 4.507G | 852M → 802M (−5.9%) |
  | `sorting` | 841M → 840M | 486M → 483M |
  | `startup` | 35.3M → 33.3M | 12.0M → 10.5M |

  The instruction counts are the same, so the interpreter does the same work. What changed is how many
  cycles that work takes: about 5% either way, with `branches` gaining what `funcs` and `globals` lost.
  That pattern points to a PGO build placing code differently, not to a change in the code. The cycle
  counts are a single sample each, taken outside `--exclusive`.
- `branches` 192.1 → 181.8 (−5%) and `sorting` 107.8 → 102.4 (−5%). `sorting` has recovered most of the
  +9% the last run showed, and its instruction count did not move, so that +9% was not slate's either.
- `startup` 2.7 → 3.3 ms in the table, although it now counts fewer instructions and fewer cycles. That
  is the noise of a 3 ms measurement.
- Everything else is within ±4%, the same band the yardsticks moved in.
