# 2026-09-24 — sysl 0.0.130: fewer instructions, MORE time, so the floor does not move

**Superseded by [sysl 0.0.131](2026-09-24-sysl-0-0-131.md)**, which fixed the cause (a
store-forwarding stall in the library's `Buf.push`) and moved the floor to 0.0.131. This page is
kept as the measurement of the regression.

**A compiler pickup that measured the wrong way round.** 0.0.130's generic-struct invariant makes
`Buf.at` one compare, and on slate it does take instructions out — the PGO binary retires 0.2–8.4%
fewer on twenty of twenty-three programs. It is still **slower**: the same tree built by 0.0.130 runs
**+2.10% and +2.93%** on the geometric mean against the same tree built by 0.0.129 (two alternating
best-of-9 runs, PGO against PGO), and **+5.31%** plain against plain. `globals` is +31.9% / +37.8%
PGO and +23.3% plain. The instructions went down and the cycles went up.

The branch raised `package.hocon`'s floor to 0.0.130 on the premise that an older compiler builds
this source slower. On this machine it is the other way, so the branch is **not landed**.

**`globals` on the PGO pair, one run each: 3.83 G instructions in 454 M cycles against 3.64 G in
565 M** — IPC 8.4 to 6.4. So 0.0.130's code does less work and stalls on it; whatever the invariant
changed in the shape of the hot path (a load the check now depends on, a branch that predicts worse,
alignment), it costs more than the compares it removed.

**`run_frames` is larger**: 58,376 bytes (14,594 instructions) in the 0.0.129 PGO binary and 65,216
bytes (16,304) in the 0.0.130 one, measured symbol to next symbol.

## What this means

- **The floor stays at 0.0.129** and the CI pins stay with it. The only argument for 0.0.130 was
  speed, and on this machine and this tree it is slower on both build shapes.
- **This is a sysl finding, not a slate one**: the same source, two compilers, and the newer one's
  binary regresses by 2–5% on the mean and a third on `globals`. The −5.47% the buf-invariant work
  reported does not reproduce here; reconciling the two (which tree, which binaries, which order) is
  the sysl side's.
- `globals` and `funcs` are the reductions to start from — the largest, most consistent regressions,
  and `globals` shows it in cycles against fewer instructions in a single run.
