# 2026-09-24 — A CALL HANDING ITS PARAMETERS ON, PROVEN BY THE FRAME'S MASK: REFUTED

The follow-up both [`never-absent`](2026-09-23-never-absent.md) and
[`never-absent-2`](2026-09-24-never-absent-2.md) named: the unmarked fifth of the suite's calls was
said to be "a parameter passed straight on", which the compiler cannot prove because a caller may
have left it out. This makes that a run-time fact. Control dev `ec9aaac`; branch `given-all`.
**Not landed**: the gain is under 1% on the mean and under 3% on every mover.

## What changed

- **A GIVEN MASK in the call's packed count** (`code.sysl`): bits 16–29, one per parameter of the
  chunk the call is written in, below `AnswerUnused`. The count keeps sixteen bits (`ArgcBits`).
- **`given_mask`** (`compile_expr.sysl`): a call whose every argument is proven or is a bare read of
  one of this chunk's own parameters carries those parameters' bits instead of `KeptArgs`. A
  parameter whose default has run is proven outright (`defaulted_here`), except in the HEAD, where a
  default may read a parameter to its right that has not been filled yet (`Emit.in_head`).
- **Both in-place arms and `standing_native`** skip the per-argument refusal where
  `kept_by_given(packed, given)` — the running frame's `JumpIfGiven` mask covers the call's bits,
  one `and` and one compare, taken only where `KeptArgs` is absent.
- **The profile files such a call as `CallFnGiven` / `CallMethodGiven`.**

## How many calls it reaches

`--features profile`, `SLATE_PROFILE=1`, the 23 programs, control against branch:

| program | control kept / unmarked | branch kept / given / unmarked |
|---|---|---|
| `options` | 2 / 4,000,000 | 2 / **4,000,000** / 0 |
| `dispatch` | 2 / 5,000,000 | 2 / 0 / 5,000,000 |
| `csv` | 680,063 / 1,200,001 | 680,063 / 0 / 1,200,001 |
| every other program | unchanged | unchanged |

**Only `options` hands a parameter on.** `dispatch`'s loop is `kind(words[i % 6])` and `csv`'s is
`number(parts[0])` — both an ELEMENT, which can genuinely be an absence (an index past the end
answers one), so no mask can prove them. The premise that all three were parameter forwarding was
wrong for two of the three, exactly as `never-absent-2`'s premise about call answers was.

the layout scatter the earlier items saw.

## Found on the way

**A default reading a parameter to its RIGHT disagrees between the back ends.** `early(a = t(b),
b = 2) = a` called `early()` faults in the interpreter with "cannot be passed to a function" (the
slot is padded with the absence) and under `slate js` with JavaScript's `Cannot access 'b' before
initialization` — even `early(b = 3)` throws there. `docs` says a default sees "none to its right";
neither back end refuses it at compile time.
