# 2026-09-23 — A PROTO HIT IS ONE LOOK — profile 6's item 5

Profile 6's item 5. On `methods.sl` a method reached through a class cost, per call: an own-field
probe at the remembered position (a miss), `obj_index_hashed` on the receiver's own table, the
remembered hop and hit, a `name != "new"` string comparison, and the retain and release of the name
taken out of `u.strings`. `GetField` of an inherited name paid the own-field probe twice on top. The
item's question was how to say "the instance has not gained this name since" in O(1). It turns out
the answer was already on every table.

Control `bdf593e` (dev, thin LTO in the manifest, both sides built with sysl 0.0.128); branch
`proto-hit`.

## What changed

**The key summary is the witness.** `ObjectObj.keys_bloom` has one bit per hash bucket, and every key
a table takes sets its bit in `entry_push`. Nothing clears a bit short of emptying the table, so
`obj_lacks(o, h)` answers "certainly not an own field" in one shift and one `and`, and it is exact in
the direction that matters. Of the brief's three options this is (c), and it needed no new state. A
per-object write counter (a) cannot tell two instances apart at a site that sees both. An own-key
count (b) is never zero for a class instance, since its fields are table entries. The profile read
step 3 as a scan of the table, but for `methods.sl` the summary already refuses at that point:
`dot` → bit 32 and `scaled` → bit 15, while `x`/`y`/`proto` → 7/20/49. So the cost was the path
around the check, not the check itself.

`field_from_site` (`site_cache.sysl`) now starts with the summary:

- **it lacks the name**: check the remembered `proto` hop and the remembered position on the proto,
  each against the key standing there. On a hit, answer `(value, true)`. There is no own-field probe
  and no search. The receiver needs no string comparison, because a site whose name hashes the way
  `"new"` does is sent the long way first. That is `Unit.new_hash`, hashed once beside `proto_hash`.
- **it may hold the name**: probe the own position as before, then search, then hop, then walk. Only
  here is the name taken out of the unit's table.

`field_named` is `field_here` for the name at place `k`. It compares `p.s == u.strings.elems[k]` where
the string stands, so a hit takes no `string` out of the table. `read_field_site` uses it for the
own-field hit that `GetField` makes on nearly every read, and reads the name only for the absent path.
`field_from_site` takes `k` rather than `name` and `h`, which accounts for `run_frames.sysl`'s whole
diff (one argument list; the file stays at 997 lines).

**Semantics are unchanged, and every way the remembered answer can go stale is a miss:**

- an instance that **gains** the name sets its bit, so the next call goes the long way and finds it;
- a name **removed** (by `without`, or `obj_drop_at`) leaves its bit set, which costs a search and
  never changes an answer;
- a **proto replaced**, a **method reassigned** on the proto, or a table **rehashed** means a
  remembered hop or hit whose key or position no longer matches;
- a **nearer proto** that gains the name is found because the hop's value is read fresh on every
  call, and the cached hit is checked on that object and not on the old one.

**Tried and reverted: taking the name out of the `CallMethod` arm too.** It is held there for
`shape_receiver`/`universal_receiver` and the complaints. A build that read it lazily measured no
better than one that holds it (the "variant" run below), so the arm keeps its `val name` and the
branch touches `run_frames.sysl` in one line.

## The numbers

Alternating best-of-9 (`bench/alternate.pl 9`), with `pgrep -x java` empty before every run. The
box was 80–90% idle, because another session's sbt came and went and each run waited for it to
finish. There were three runs of the landed shape (the first two with the lazy arm, the third
exactly as landed) and one of the variant:

| program | run 1 | run 2 | variant (arm holds `name`) | **as landed** |
|---|---|---|---|---|
| **methods** | −14.6% | −14.1% | −20.7% | **−10.4%** (419.5 → 375.8 ms) |
| **fields** | −12.9% | −11.3% | −13.6% | **−12.4%** (203.6 → 178.3 ms) |
| **calls** | −3.5% | −3.9% | −3.1% | **+0.5%** (326.6 → 328.4 ms) |
| options | −13.5% | −10.6% | −19.2% | −10.1% |
| nested | −14.1% | −11.6% | −19.6% | −7.7% |
| dispatch | −10.4% | −10.2% | −22.8% | −7.8% |
| branches | −18.9% | −19.3% | −19.7% | −17.2% |
| arith | −12.1% | −7.6% | −8.8% | −7.1% |
| sorting | −0.5% | −0.2% | +0.1% | +0.7% |
| strings | −1.3% | −0.8% | +4.0% | +1.2% |
| **GEOMEAN** | −9.10% | −7.66% | −9.64% | **−5.33%** |

**The read-worthy half of this table is the rows that CANNOT be this change.** `branches` and `arith`
read no field and call no method. Their only dots are in comments. Yet they move 7–19% on every run.
Under thin LTO `read_field_site` and `field_named` are inlined into `run_frames`, so this change
alters the code and register allocation of the whole dispatch loop. What reaches every program is
that loop's new layout, not work removed from it. That effect is real and repeatable for this binary
(`branches` −17 to −19% on all four runs), and it is also exactly what the next change to
`run_frames` may take back. **Treat the geometric mean as an upper bound for this item.** The rows
the item is about are `methods` and `fields`, at −10 to −15% and −11 to −14%, and even those carry
some of the layout term.

**The witness is `sample`** (`bench/profile.sl --duration=5`, same box, back to back). Everything is
inlined into `run_frames` under LTO, so per-function shares no longer attribute anything, and the
witness is the sample total:

| program | control samples | branch samples |
|---|---:|---:|
| methods | 339 | 271 |
| fields | 137 | 114 |
| branches | 238 | 191 |

`field_from_site` is still its own symbol, at 19 → 26 samples: more of the call's work now happens
inside it and less in the inlined probes around it. `Buf.at<string>`, profile 6's 2.5%, does not
appear on either side. Under LTO it is inlined wherever it remains.

No `Op` changed, so instruction counts are identical to the instruction.

## Tests

- `tests/lang/sitecache.sl` (both back ends, 23/23 each). Six new tests: a method-call site that hit
  the class finds a field the instance gains afterwards; one site alternating between an instance that
  shadows the method and one that does not; a `without` copy that drops the shadowing field reaches
  the proto again; a proto replaced under a method-call site, then a method reassigned on the proto
  now reached; a nearer proto gaining the name wins over the one reached before, and an own field wins
  over both; `new` reached through an instance is handed no receiver at a remembered site.
- `tests_site_cache.sysl`. `Unit.new_hash` equals `"new".hash()`. An instance whose own field shares
  the method's summary bit (found by search, `same_bit_as`) still reaches the class over 2,000 calls
  and then finds the method it gains. The one-look path at its commonest (`Vec.dot` over 1,000 calls,
  receiver and argument both read) answers the exact sum. A constructor called through an instance a
  thousand times answers the exact sum.
