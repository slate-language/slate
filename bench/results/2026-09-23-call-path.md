# 2026-09-23 — THE CALL PATH STOPS ALLOCATING: A TABLE PER OBJECT, A LIST PER SPLIT, AND THE METHOD TABLES PER CALL

The shortlist's row 7, *"what `calls` and `csv` allocate per call — an open question, not yet an
item"*, answered, and what was left of item 11 with it. The three worst programs against CPython were
`calls` (2.9x), `csv` (3.0x) and `methods` (2.2x). `sample` on each named four costs, and all four
are gone:

1. **An object's entry table was a `malloc` and a `free` per object.** An `ObjectObj`'s fields live
   in a `Buf[Entry]` outside the heap, and a `Buf` grows to **eight** entries at its first push. So
   `Counter(self.n + by)` asked `malloc` for eight entries, wrote all eight (`Buf.grow`'s fill), and
   the sweep that freed the object handed them to `free`. That was 2,000,000 of each in `calls.sl`.
2. **`split` built its answer twice.** `do_split` called `sysl.text.split`, which answers a
   `[]string` it grows in a `Buf[string]` of its own, then copied every piece into the `Buf[Value]`
   the slate array is made of and threw the first list away. A `malloc`, a fill and a `free` per
   call, 600,000 of them in `csv.sl`, for a list only that loop ever read.
3. **A method call on a builtin kind asked the tables every time.** `line.split(",")` went
   `builtin_receiver` → `methods_of(method_kind(v), name)`, which is a chain of word comparisons on
   the kind (`"array"`, `"bytes"`, `"string"`…) and then another on the name. This is the part of
   item 11 that was left: `methods_of` looking a method up by name at every call.
4. **Entering a function copied its whole `Chunk` out of the table.** `placed_call` wrote
   `val chunk = u.chunks.at(c.body)`, which is 136 bytes and three counted members retained on the
   way out and released at the end, plus an out-of-line `Buf.len` for `chunk.params.len()` — to read
   four flags and four numbers. Once per call, on every program that calls.

Control `9d794de` (dev, slate 0.1.3); branch `call-path`.

## What changed

- **A sweep keeps a small object's table and the next object takes it.** `finalize_object` in
  `obj.sysl`: where a sweep is running (`Vm.sweeping`, set by `collect_now` around `gc.collect`) and
  the table is exactly the first-push size, it is emptied and pushed onto `Vm.spare_entries`, up to
  1,024 of them (half a megabyte). `new_object` pops one before it asks for memory. The charge is
  unchanged: `new_object` already charges `object_payload`, which is the kept table's capacity, and
  that is exactly what the first `entry_push` used to charge.
  - **A disposed heap keeps nothing, and `dispose_vm` now enters the VM it disposes.** The finalizers
    run with that VM current, so `finalize_object` asks the disposed VM's own `sweeping` — `false`.
    Before, `dispose_vm` ran them with whatever VM the thread was left in, and on an actor's thread
    that is the MAIN VM, sweeping on another thread; a finalizer that consulted it would have pushed
    the actor's tables into main's list from the wrong thread. `CLAUDE.md`'s *"a finalizer touches no
    VM state"* now reads *"touches only the VM being swept"*.
- **`do_split` cuts the pieces itself** with `index_of_from`, straight into the answer's `Buf[Value]`.
  Every rule is the library's: empty pieces are kept at both ends, a multi-byte separator is matched
  whole, no separator is one piece.
- **A `CallMethod` site remembers the builtin it found, keyed on the kind.** `SiteCache` grows two
  fields (`kind: u32`, `native: NativeFn`), `method_kind` becomes `kind_word(method_kind_code(v))` —
  one match from variant to number, one from number to word — and `builtin_from_site` in
  `site_cache.sysl` answers from the site where the kind matches. **A remembered VALUE is sound here
  where it is not for an object**: the tables are fixed when slate is built and are the same for every
  value of a kind, and a site's name never changes. Kind `0` (an external, an actor) and a name the
  kind lacks are never remembered, so every complaint is still `builtin_receiver`'s.
- **`placed_call` reads the chunk where it stands** — `&u.chunks.elems[i]` and a field — so the only
  counted member touched is `code`, the one the frame keeps. The disassembly goes from a 136-byte copy,
  three retains, a `bl Buf.len.string`, a second retain and three releases to four byte loads and one
  retain.

No `Op` changed, so instruction counts are identical to the instruction; `run_frames.sysl` stays at
999 lines (one arm's callee renamed).

## The tests

- **`tests_call_path.sysl`** — six: a sweep keeps a one-field object's table and the next object gets
  it EMPTY (no stale `a`, one field after one write, no growth); the kept list stops at 1,024; a table
  that grew past eight is given back rather than kept; the payload recount is exact over objects built
  on kept tables; a disposed heap keeps nothing **while the VM this thread is in is marked mid-sweep**,
  which is the negative control for the `enter` in `dispose_vm`; every kind number 1–23 has a word of
  its own, 0 and 24 have none, and an integer and a real are one kind.
- **`tests/lang/sitecache.sl`** — one call site meeting a string, an array, a string, an array answers
  each with its own `at`; a site that remembered a string's `split` still refuses an array's, in the
  ordinary sentence, and then answers a string again; one `toString` site serves integers and reals.
- **`tests/lang/strings.sl`** — `split`'s empty pieces at both ends and between, a two-byte separator,
  a separator longer than the text, the empty string, the method form, and pieces of a multi-byte
  string counting their own characters.

`767 passed` on `slate test tests/lang` and on `slate test --js tests/lang`.

## What is left

`calls` still pays `hook_of(callee, "new")` per construction — a name lookup on the class, hashing
`"new"` — which a site cache on `CallFn` would take, `CallFn` having no site of its own today. `csv`'s
remaining allocation is the piece strings themselves, a `StrObj` owning a sysl `string` each, which
only a small-string form of `StrObj` would change; and its `number`/`string` calls still resolve their
names through `lookup` at run time.
