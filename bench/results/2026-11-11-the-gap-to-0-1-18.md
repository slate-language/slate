# Where the speed lost at 0.1.19 went, and what is left of it

slate 0.1.19 was 47% slower than 0.1.18 on the geometric mean, and the only slate source change between
them beyond file splits was one `Buf.copy`: 0.1.19 was the first release built by the self-hosted sysl.
This profiles the three release binaries to find what the compiler changed in the code that runs.

## Method

Each binary is its release tarball's (0.1.37 is the PGO build `bench/pgo.sh` made for the release).
The program is `fib(38)`, `bench/fib.sl` at a larger argument so each run lasts two to four seconds:

```
fib(n) = if n < 2 then n else fib(n - 1) + fib(n - 2)

print(fib(38))
```

Counts are from `/usr/bin/time -l`. The profile is Instruments' Time Profiler (`xctrace record
--template 'Time Profiler' --launch`), read from the raw `time-sample` table, whose `kperf-bt` carries
the sampled program counter. The `time-profile` table's backtraces fail to unwind 0.1.19 for 98% of
its samples, so it cannot be used for this comparison. Each counter is rebased by the binary's load
address and laid against `objdump -d` of the function it falls in. "Hot code" below is every
instruction inside a run of sampled instructions with gaps of at most six.

## Counts

| release | instructions | cycles | time |
|---|---:|---:|---:|
| 0.1.18 | 55.7G | 8.07G | 2.09 s |
| 0.1.19 | 86.5G | 14.63G | 3.82 s |
| 0.1.37 | 68.0G | 10.71G | 2.84 s |

`fib(38)` makes 126 million calls: 442 instructions a call in 0.1.18, 686 in 0.1.19 and 539 in 0.1.37.

## Where the samples fall

98 to 100% of every binary's samples are in one function, `run_frames`, the interpreter loop. The
opcode dispatch (bounds check on the code index, load of the 32-byte instruction, jump-table branch)
compiles to the same eleven instructions in all three and takes the same share of samples. The
difference is all in the opcode handlers.

| release | hot instructions | loads | stores | branches | ALU | retain/release pairs |
|---|---:|---:|---:|---:|---:|---:|
| 0.1.18 | 307 | 97 | 27 | 63 | 120 | 0 |
| 0.1.19 | 560 | 177 | 76 | 138 | 169 | 11 |
| 0.1.37 | 361 | 107 | 37 | 62 | 155 | 0 |

**What 0.1.19 lost was reference counting in the loop**: eleven retain/release pairs on counted
buffers inside the hot handlers, each release a load, decrement, store and branch to free, and twice
the branches. Releases since have removed every one of them, which is most of what has been won back.

## What 0.1.37 still pays

Against 0.1.18 the hot code is 54 instructions longer. By opcode, the largest differences are:

| opcode | 0.1.18 | 0.1.37 | change |
|---|---:|---:|---:|
| `ldr` | 57 | 86 | +29 |
| `csel` | 1 | 25 | +24 |
| `ldur` | 22 | 0 | -22 |
| `str` | 16 | 30 | +14 |
| `cmp` | 45 | 56 | +11 |
| `add` | 33 | 43 | +10 |
| `stur` | 11 | 1 | -10 |
| `stp` | 0 | 6 | +6 |

The `ldr`/`ldur` and `str`/`stur` swaps are only addressing forms. **The 24 `csel`s are all one
pattern**: load a buffer's block pointer, test it for null, and select either a shared empty block or
the block's data, then load through the result:

```
ldr   x8, [x17]            ; the buffer's block pointer
add   x9, x8, #0x18        ; its data, past the header
cmp   x8, #0x0             ; a buffer with no block is empty
csel  x19, x6, x9, eq      ; so read the shared empty one instead
ldp   x9, x8, [x19, #0x10]
```

That is three instructions and a dependent load on every buffer the loop reads that 0.1.18 read as a
plain pointer and length. The extra stores, five of them to the stack, look like values kept in
memory rather than registers.

## What follows

The null test exists because an empty buffer may have no block at all, and slate depends on that: a
new object leaves its `index` as `gc.alloc` zeroed it and reads it as empty for its whole life.

sysl measured the alternatives on an interpreter-shaped probe at -O2. Dropping the test outright went
9.67G to 7.86G instructions, and it breaks that zeroed `index`. A `cbz` per member is 8.46G (-12%), but
it costs buffer loops their hoisting and vectorisation (+6 to +18%), which is what the `csel` buys. So
sysl 0.10.0 keeps today's read.

The form that wins both ways is a compiler-known handle whose zero names a static sentinel, so that a
read is one add of a base that can be hoisted and a zeroed field is still a valid empty buffer. That is
now a requirement of sysl's queued `Slots[T]` handle, in the speed pass after 0.10.0, and slate needs
no change for it.
