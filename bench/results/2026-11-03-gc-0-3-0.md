# slate 0.1.36: gc 0.3.0 and sysl 0.8.15

Every binary is a PGO build from `bench/pgo.sh`, and each comparison is `bench/alternate.pl 5`: the two
binaries run alternately, program by program, and the lowest of five rounds is kept. Times are
milliseconds, all taken under `caffeinate`, with the box at 86.0% idle or better before each run.

gc 0.3.0 is a breaking redesign: a heap carries a context, a finalizer is handed the heap it runs in,
the mark ignores any pointer outside the arena's used part, and the header shrinks to three words with
no object list, so dispose and the weak passes walk the arena in address order. slate passes a null
context and keeps finding its VM from the heap's address; `finalize_object` now asks that VM instead
of the current one, so disposing a VM no longer has to enter it.

## The candidates, one step at a time

Each step is one gc commit on the way to 0.3.0. A is gc 0.2.10 under slate 0.1.35's source; B to E are
slate's adapter on each candidate.

| step | gc change | geomean |
|---|---|---:|
| A vs A | noise floor | -0.49% |
| A to B | the 0.3.0 API: heap context, `kind_of`, finalizer handed the heap, `checks` | +0.08% |
| B to C | four-word header | +0.37%, -0.33% reversed |
| C to D | range-checked mark | +0.18% |
| **A to D** | | **-1.06%** |
| D to E | three-word header, no object list | -0.07% |

B to C first read +1.16%; the two re-runs above put it at about 0.35%. All five builds retire the same
instructions on `sorting` (857M), so that first reading was B's lucky layout.
