# 2026-09-22 — sysl 0.0.124: `Buf.push` inlines outright for a counted element

**A follow-on to the 0.0.123 pickup, not a new shortlist item.** 0.0.123 moved `Buf.push`'s grow path
`@noinline @cold`, which let the ordinary store-and-bump inline at every hot call site. 0.0.124 goes
further for a **counted element** — slate's `Value`, which every array and object push in the
interpreter is — inlining the push outright rather than leaving a call to a generic instantiation.
sysl's own micro-bench reports **1.85x** on push/pop of a 40-byte counted struct. This is a compiler
change and nothing under `dev/` moved: `package.hocon`'s floor is the whole diff.

**Measured: geometric mean -2.08% on the alternating best-of-9**, against sysl 0.0.123 built from the
same commit. The biggest movers were `startup` (-9.5%), `closures` (-6.7%), `funcs` (-5.6%), `loops`
(-4.4%), `arith` (-4.1%), `nested` (-4.1%), `fields` (-4.0%), `fib` (-3.2%) — the same shape of
programs the 0.0.123 write-up named as `Buf.push`-bound, since a narrower slice of the same call is
what this item moves.

**Not every program moved the same way this time** — five of twenty-three read slightly slower, all
within about a point and a half, which is the noise band this method usually shows on a program that
was never `Buf.push<Value>`-bound (`globals`'s loop pushes almost nothing; `csv`, `strings` and
`arrays` build with fewer, larger pushes rather than many small ones). The programs that *are*
push-heavy in a tight loop — `closures`, `funcs`, `loops`, `arith`, `nested`, `fields`, `fib` — all
moved the same direction, and `startup` moving the most is consistent with the change touching the
compiler's own runtime prelude rather than only user code.

**Method**: alternating best-of-9 (`bench/alternate.pl 9`), box at 94.5% idle before the run,
`pgrep -x java` empty throughout, run under `caffeinate -dimsu`.

## The witness: `Buf.push<Value>`'s self time on `methods.sl`

`/usr/bin/sample` at 1 ms, `bench/methods.sl`, self time from "Sort by top of stack" against the main
thread's own sample total — control and branch each sampled once, same dev commit, same machine state
(94–95% idle, `pgrep -x java` empty).

| | control (sysl 0.0.123) | branch (sysl 0.0.124) |
|---|---|---|
| samples (main thread) | 436 | 396 |
| `Buf.push<Value>` self time | 6 / 436 = **1.4%** | 3 / 396 = **0.8%** |

A single sample at this size is noisy — the two counts are 6 and 3 against denominators that
themselves moved, since the branch also runs the whole program faster — so this is corroborating
rather than the primary evidence; the alternating best-of-9 above is the number this item is measured
by. `Buf.push<Value>` was already down from 16.2% (pre-0.0.123) to 1.9% by the 0.0.123 pickup, so what
is left to move here is a small fraction of a program that was never dominated by this one call in the
first place — consistent with a real but modest further win.

## What this closes and what stays open

**No shortlist line is struck by this pickup.** Item 1 (inlining `Buf.push`'s common path) was already
struck at 0.0.123; this is the same compiler mechanism carried one step further for the specific case
of a counted element, found and fixed on sysl's own side rather than from a slate profile. Item 8 (a
narrower `Value`, or NaN-boxing) is unaffected — `Buf.push<Value>`'s reach figure there was already
stale after 0.0.123 and the third sampled profile (dev `a642e9f`), and stays stale here for the same
reason: every compiler-level `Buf.push` change moves underneath that item without a slate-side change
to explain it.

**Nothing under `dev/` changed.** The whole of this item is `package.hocon`'s floor plus a newer
compiler, exactly as the 0.0.123 and 0.0.122 write-ups above were.
