# 2026-09-23 — sysl 0.0.126: a by-value counted parameter is BORROWED, and the caller decides

**A compiler pickup, not a shortlist item, and the largest one of these so far: geometric mean
**−4.48%** and **−4.58%** over two alternating best-of-9 runs, on dev `6779890`.** Nothing under
`dev/` moved — `package.hocon`'s floor and the two `SYSL_VERSION` workflow pins are the whole diff,
and the instruction counts are identical to the instruction.

What 0.0.126 changes is the **calling convention for a by-value counted parameter**. A callee used to
retain at entry and release at exit, whatever it was handed; now the **caller** decides, and a
temporary, a string literal and a local nothing else can reach are handed over for free. Only a
memory place — a field, an array element, a global — pays the retain/release, and it pays it at the
call rather than inside the callee. sysl's own push/pop micro-bench reads 24% faster.

The interpreter is built almost entirely out of that case. `Buf.at`, `Buf.push` and `Buf.len` all take
`self` **by value**, and every one of them is called with a `*Buf` field of the running machine — so
the dispatch loop, `placed_call`, `lay_standing` and every field read were paying a count pair per
call on a slice nobody could have freed. That is what the programs below are reporting.

The release also lets a pure `ensures` clause reach the optimizer as an `llvm.assume`, so
`Buf.grow`'s post-condition folds the store bounds check inside `push`; it carries a Scala 3.9.0
toolchain; and it fixes `sysl vendor .`.

## The witness, and why it cannot be an ARC frame

**There is no `arc.copy` or `arc.dispose` symbol to sample: sysl's retain and release are INLINED
arithmetic on the count word, not calls.** `grep -c arc` answers **0** on all four sample files, on
both compilers. So the sampler cannot attribute the saved work to a named frame the way it attributed
`Buf.push<Value>` at 0.0.123 — what it can show is where the time went instead, and the deterministic
counters are what say the program did not change.

`/usr/bin/sample` at 1 ms, one sample per binary per program, same dev commit, box at 94% idle:

| | `calls` control | `calls` branch | `methods` control | `methods` branch |
|---|---|---|---|---|
| samples (main thread) | 310 | 320 | 394 | **312** |
| `run_frames` self | 65 = 21.0% | 63 = 19.7% | 183 = 46.4% | 134 = **43.0%** |
| `_xzm_free` self | 10 = 3.2% | 9 = 2.8% | under the 5-sample cut | under the cut |
| `_xzm_xzone_malloc_tiny` self | under the cut | 9 = 2.8% | under the cut | under the cut |
| `field_here` self | 6 = 1.9% | under the cut | 37 = 9.4% | **under the cut** |
| `read_field_site` self | 5 = 1.6% | under the cut | 28 = 7.1% | 49 = 15.7% |

Two things are legible in that and the rest is noise at one sample apiece:

- **`methods` takes 312 main-thread samples where the control took 394** for the same program at the
  same rate — the wall-clock result arriving in the sampler, and the same direction as the -12.8% both
  best-of-9 runs give.
- **`field_here` is gone from the branch's profile and `read_field_site` has grown by about what it
  held** — the field-read hit path folded into its caller once the borrow stopped standing between
  them. That is `-O2` inlining differently because the call is cheaper, which is the mechanism doing
  what it says.

**The malloc family did NOT move, and that is the useful negative.** `_xzm_free` reads 3.2% against
2.8% — inside the instrument — so this is not the allocator getting less work; it is the count pairs
that never reached it. The counters agree:

## Instruction counts are identical to the instruction

`sysl build . --features profile` on both sides, then `SLATE_PROFILE=1` on each program:

| | control | branch |
|---|---|---|
| `calls` instructions | 48,000,046 | 48,000,046 |
| `methods` instructions | 111,000,068 | 111,000,068 |

Per-op, identically: `calls` — `Tick` 6,000,009, `LoadSlot` 6,000,002, `Ret` 4,000,003, `CallFn`
2,000,003, `GetField` 2,000,001; `methods` — `LoadSlot` 27,000,005, `GetField` 18,000,000, `Tick`
9,000,012, `Ret` 6,000,004, `CallFn` 4. **Nothing about the emitted program changed** — the whole of
the difference is the machine code sysl produced for the interpreter that runs it.

The binary grew with it: 5,687,384 bytes to 5,863,048, **+3.1%**. A caller that decides the borrow
writes the decision at every call site, and a callee that no longer retains at entry inlines more
readily; both spend text.

## dev moved underneath this, and the measurement is still the branch point's

`one-jump-table` landed on `origin/dev` while this was being measured, so the tree this merges into
is not the tree the tables above were taken on. **Both binaries are dev `6779890`** — the branch
point, before that item — which is what makes the comparison a comparison of the two compilers and
nothing else. The gate ran on the merged tree and nothing under `dev/` is this branch's, so the merge
carries no risk to the numbers; what it does mean is that the two items' effects have not been
measured together, and `methods`, `fib` and `dispatch` are named by both.

## What this closes and what stays open

**No shortlist line is struck.** This is a compiler pickup, like 0.0.122, 0.0.123 and 0.0.124 before
it; the ranked shortlist is profile 5's and is untouched. What it does do is move the floor under
every item left on it — the dispatch head is now a larger share of a smaller loop, and profile 5's
fitted `D = 1.67 ns` was taken against a build that paid a count pair per `Buf.at`. **A sampled
profile taken before the next head item is picked up will read differently from profile 5's**, and
that is worth knowing before anything on the list is priced from those numbers.
