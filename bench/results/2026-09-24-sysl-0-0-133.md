# 2026-09-24 — sysl 0.0.133: three libraries linked statically, and the shortest-real workaround gone

**sysl 0.0.133 carries two things slate wanted.** The manifest's new `link` key takes a library a
build finds through `pkg_config` from its static archive, and `display_real_shortest` is now Ryu, the
true shortest round-trip digits by JavaScript's rule. `package.hocon` now says
`link = ["libuv", "libssl", "libcrypto"]`, and `decimal.sysl`'s `shortest_reading` workaround is gone.
The floor moves to **0.0.133**, and both `SYSL_VERSION` pins move with it.

The static link takes the dynamic loader's cost off every run. `startup` drops **−21.9%**, `strindex`
**−19.5%** and `strwalk` **−12.9%**, and the geometric mean moves **−3.69%** (PGO against PGO,
alternating best-of-9). Linking **all eight** Homebrew libraries statically is worth twice that:
**−8.80%**, with `startup` at **−45.6%**, which is qjs parity. The manifest cannot say that yet, for a
reason given below.

## Which libraries, and why only three

Every library slate links through Homebrew has an archive beside its dylib (`ls
/opt/homebrew/opt/<x>/lib/*.a`). PCRE2 is no longer linked, since `slate:regex` is on vendored
libregexp. Eleven `pkg_config` names are in a default build: `libuv`, `libssl`, `libcrypto`, `lmdb`,
`libnghttp2`, `hiredis`, `libbrotlidec`, `libbrotlienc`, `libwebp`, `libzstd` and `sqlite3`.

- **`link = "static"` is refused** by `sqlite3`, which is the system's `/usr/lib` copy and has no
  archive: `'sqlite3' is to be linked statically, and there is no 'libsqlite3.a' to link it from —
  looked in /usr/lib`.
- **A list naming an OPTIONAL library is refused by every build that leaves its feature out.** The
  refusal is `sysl build . --no-default-features --link libuv,lmdb` → `'link' names 'lmdb', and no
  pkg_config requirement in this build is called that — … which here are libcrypto, libssl, libuv,
  sqlite3`. So `lmdb`, `libnghttp2`, `hiredis`, `libbrotli*`, `libwebp` and `libzstd` cannot be in
  the key without breaking the `--no-default-features` gate shape.
- **The three that stay are in every build and have an archive on both release platforms.** On
  macOS that is Homebrew's. On Linux it is the static libuv 1.51 that `scripts/linux-deps.sh` builds
  and Debian's `libssl-dev`, which ships `libssl.a`/`libcrypto.a`. The other five Linux libraries
  that script builds were already static through their `.pc` files.

**This is a sysl finding and it has been reported rather than worked around.** Two fixes would let
the key say "all of them": a `link` name that no *enabled* dependency asks for could be ignored when a
feature that is off declares it, or the key could be allowed per feature. Until one lands, the other
six stay dynamic.

## The shortest-real workaround

The old sysl printer asked `printf` for digits and broke ties to the even digit, so `2^-24` came out
as `5.9604644775390625e-8`, one digit longer than needed. `shortest_reading` in `decimal.sysl` brought
the count down with exact rounding and a `parse_real` round trip. 0.0.133's library answer is already
the shortest by JavaScript's rule, so `real_shortest` in `render.sysl` now takes those digits as they
stand. The one thing `shortest_reading` also did was take off a whole number's trailing zeros
(`100.0` → `1e+2`), and that is now three lines in `real_shortest` itself. `reads_back`, the
`parse_real` import and `digits_text`'s cross-file use went with it.

**The proof is the existing corpus, unchanged.** `tests/js/p40.sl` checks about 60 values on both back
ends and `tests_reals.sysl` covers the rest. Two tests are added:
`A_TIE_AT_SOME_PRECISION_STILL_PRINTS_THE_FEWEST_DIGITS_THAT_READ_BACK` (`2^-24` through `print` and
`toExponential`) and `A_WHOLE_REAL_NAMES_ITSELF_WITHOUT_ITS_TRAILING_ZEROS`.

**No test reads the built binary's census.** sysl has no way for a test to name the executable it
built, so the census is pinned here rather than in the suite.
