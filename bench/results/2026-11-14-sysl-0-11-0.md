# slate on sysl 0.11.0, against the seven yardsticks

The binary is a `bench/pgo.sh` build of dev `5b8de11` (sysl 0.11.0, libuv 0.1.22, kairos 0.1.19, gc
0.3.2) — 0.2.0's tree plus the 0.11 move. `bench/check.sh` first: every twin's answers unchanged. Then
`bench/run.sh -n 5`, best of five wall times in milliseconds, run as a `marshal run --exclusive` job:
it started only once no other marshal job was running and nothing else was admitted until it ended.
Its log samples the load every 30 s; the one-minute figure stayed between 1.5 and 2.0 through the
run, and the busiest process outside marshal was WindowServer at about 5%.

which was taken on a busy machine — so that run was not distorted by the load either.

## `fib`, which does not depend on the load

`bench/fib.sl` under `/usr/bin/time -l`:

| release | instructions | cycles |
|---|---:|---:|
| 0.1.18 | 5.06G | 634M |
| 0.1.32 | 6.31G | 1017M |
| 0.2.0, sysl 0.10.1 | 6.16G | 861M |
| dev, sysl 0.11.0 | 5.91G | 865M |

Instructions fell another 4%, with cycles flat. Its wall time reads 5% slower below (182.9 → 192.9 ms)
at the same cycle count, which is the clock and not the program.

## What moved

Against the 0.10.1 table, slate's own column:

- **`sorting` 99.1 → 107.8 ms (+9%)**, the one figure that moved beyond the run-to-run spread. Lua's
  moved +2% on the same program, so most of it is slate's. Not measured further.
- `startup` 3.1 → 2.7, `loops` 113.7 → 108.0, `csv` 102.9 → 98.6: a few percent faster.
- Everything else within ±3%.
