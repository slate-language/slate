# 2026-09-24 — A COUNTED LOOP AT THE TOP OF A FILE FOLDS AS ONE IN A FUNCTION DOES

`globals.sl` is `arith`'s loop at a file's top level, where `total` and `i` are module-level `var`s
and so cells in `Vm.defs` rather than slots. After `module-vars` it was the one large program still
behind qjs: **slate 102 ms, qjs 58 ms (1.8x), Lua 102 ms** on the 0.1.6 PGO build. It is now **55 ms,
−50.6%, 0.9x qjs**.

Control `bc0b522` (dev, slate 0.1.6); branch `globals`. Both sides built with `bench/pgo.sh`.

## What the profile said

`sysl build . --features profile`, `SLATE_PROFILE=1 ./slate bench/globals.sl`: **78,000,018
instructions, thirteen a turn**:

| per turn | control | branch |
|---|---|---|
| loop head | `Tick`, `LoadCellInt`, `LessJumpIfFalse` (3) | `TickCellIntLess` (1) |
| `total = total + i * 2 - 1` | `LoadCell`, `LoadCellInt`, `MulAdd`, `PushInt`, `Sub`, `StoreCell` (6) | `LoadCell`, `LoadCellInt`, `MulAdd`, `PushInt`, `SubStoreCell` (5) |
| `i = i + 1` + back edge | `LoadCellInt`, `Add`, `StoreCell`, `Jump` (4) | `CellIntAddStoreJump` (1) |
| **total** | **13** — 78,000,018 | **7** — 42,000,016 |

The same loop in a function (`arith`) runs seven, because the slot forms of all three already fold:
`TickSlotIntLess`, `SubStoreSlot` and `SlotIntAddStoreJump` (`superinstructions-2`). Only
`LoadCell PushInt` had a cell form (`LoadCellInt`, `superinstructions-3`). The pair table named the
rest: `StoreCell Jump`, `Sub StoreCell`, `Add StoreCell` and `Tick LoadCellInt` at 7.6% of pairs each.

## The change

**The four slot runs a counted loop is made of now have cell twins**, and they do what the slot forms do,
with a cell in `Vm.defs` where a slot has a stack cell:

- `AddStoreCell(d, k)` / `SubStoreCell(d, k)` — `Add`/`Sub` then `StoreCell`. Two whole numbers whose
  answer does not overflow are written straight into a **filled** cell: no push, no pop, no
  absence check (an `Int` cannot be `undefined`). Everything else — an empty cell, a real, a string, an
  overflow — pushes the ordinary `added`/`subtracted` answer and runs `compose_store_cell` with the
  `StoreCell`'s own span, which is exactly the unfused pair.
- `TickCellIntLess(d, v)` — `Tick; LoadCell; PushInt; Less; JumpIfFalse`. The safe point, then an `Int`
  in the cell compared with the literal. Anything else runs `fused_load_cell_int` and
  `fused_less_jump_if_false` with the spans read from the slots stepped over.
- `CellIntAddStoreJump(d, v, to)` — `LoadCell(d); PushInt(v); Add; StoreCell(d); Jump(to)`, one cell
  read and written. Its slow path reads the spelling from the stepped-over `StoreCell`.

`fuse` builds them the way it builds the slot runs. It overwrites the first slot and leaves the rest
standing, and folds the inner pairs where they stand (`LoadCellInt` inside a head, `AddStoreCell`
inside a tail), so a jump into the middle finds the pair form. `MulAdd` now leaves a product summed
into a cell to `AddStoreCell`, as it already did for `AddStoreSlot`.

**The put-back had to learn one thing.** `settle_module_defs` rewrites a cell site to the by-name
instruction when the file's spelling turns out to be bound somewhere else. The site it records is the
`LoadCell`/`StoreCell` itself, but a head's `Tick` and a pair's `Add`/`Sub` stand in front of that site
and still cover it. So the put-back now also turns the instruction *before* a site back from
`TickCellIntLess`/`AddStoreCell`/`SubStoreCell` into `Tick`/`Add`/`Sub`. A tail begins at its own cell
read, so it is put back to `LoadName` like `LoadCellInt`, and the standing `PushInt; Add; StoreName;
Jump` behind it runs unfused.

`compose_store_cell` also stopped reading `u.strings.at(k)` on every write: a counted string retained
and released for a spelling a filled cell never uses. The new arms are one line each in
`run_frames.sysl`, which went from 999 to 998 lines after two comments were tightened; the bodies are in
`run_fused.sysl`.

**It survives a register machine**: each twin is its slot run with a cell operand in place of a slot
operand, so a register design would fold the same shapes.

## Position

`bench/run.sh -n 5 pgo/slate globals`, taken once on the branch's PGO binary: **slate 58.0 ms, Lua 118.1,
node --jitless 88.6, CPython 419.8, qjs 64.8** — 0.5x Lua, 0.7x node --jitless, 0.1x CPython, **0.9x
qjs**. The loop at the top of a file now costs what it costs in a function (`arith` 88 ms, which pays a
call and its frame).

## Tests

- `tests_fused.sysl` (8): the loop at a file's top level folds its head, tail and difference, and every
  run stands over its inner pair; a sum into another cell stays a pair and a product is left to the
  write; a loop whose spellings a function rebinds goes back to the lookup whole, with no fused head,
  tail, sum, difference or read left (this is the put-back's test); a step too wide for sixteen bits
  stays as pairs; a fault in a head, a tail or a difference quotes its own instruction; a string join, a
  real, and a sum or difference that leaves sixty-four bits answer the same at the top of a file as in
  a function; a refused absent write names the variable in `keepable_on`'s own sentence; and a module
  loop head collects under a small heap.
- `tests_profile.sysl` (1, `--features profile`): fifty more turns cost no more instructions at the top
  of a file than in a function, and the head, tail and difference run once a turn with no unfused
  `StoreCell` left.
- `tests_slots.sysl`: `cell_reads` counts a `CellIntAddStoreJump` as a cell read.
- `tests/lang/moduleloop.sl` (6, both back ends) with `tests/lang/lib/counted.sl`: the top-level loop
  answers what the same loop in a function answers; a closure made before the loop reads what the loop
  left and a function writes it after; a local of the same spelling is its own variable; an importer
  reads what a module's own loop finished with; a string and a real take the ordinary arithmetic; and
  writing an absence to a module variable is refused.
