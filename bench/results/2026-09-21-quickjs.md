# 2026-09-21 — a fifth runtime: QuickJS-ng, and slate's geomean against it

**Bench tooling and docs only. Nothing under `dev/` changed.** `bench/run.sh` gained `qjs` as a
fifth comparison runtime, alongside `lua`, `node --jitless`, `python3` and `node` (the last still not
a yardstick).

## Why QuickJS

Lua, CPython and `node --jitless` are each a step away from slate's own design in some direction: Lua
has a much smaller object model, CPython's is much larger, and V8's Ignition is a bytecode tier built
to be replaced by three JIT tiers slate has none of. **QuickJS-ng is a JIT-less bytecode interpreter
for a dynamically typed JS-family language** — the same design category as slate, and closer to it
than any of the other three. It is also the comparison people ask for once they hear "JIT-less
interpreter, JS-family object model."

**QuickJS-ng 0.16.2**, installed via `sudo -n -u work -H /opt/homebrew/bin/brew install quickjs-ng`
(the formula is `quickjs-ng`; `brew info quickjs-ng` shows stable now at 0.17.0, this machine has
0.16.2 installed and that is the version measured). `qjs` is on `PATH` at `/opt/homebrew/bin/qjs`.

## How it is run

**No shim needed.** The JS sources already used for `node`/`node --jitless` are reused unmodified for
`qjs`: none of the 23 benchmark `.js` files uses a node-only API (`require`, `process`, or
`performance.now` all grep clean across the set), and a direct diff of every program's stdout between
`node` and `qjs` came back identical before the timing run — `qjs` autodetects plain scripts, so no
`-m`/`-C` flag is needed either.

`bench/run.sh` calls `best qjs "$dir/$name.js"` exactly as it calls `best node --jitless
"$dir/$name.js"`, gets a `qjs/slate` ratio (`/qjs`) alongside `/lua`, `/node` and `/py`, and folds it
into the same geometric mean the other three yardsticks get (`node`-with-JIT stays out, as before, not
being a yardstick).

per-program spread below says the geomean alone understates how much that varies.

## Furthest behind and furthest ahead of `qjs`

**Furthest behind** (`/qjs` ratio highest — slate slowest relative to QuickJS):

- **`strings` — 44.6x.** QuickJS's UTF-16 string internals are simply fast here (16.8 ms for the
  whole program); slate's own string benchmark is its heaviest program in absolute terms (749.8 ms).
- **`globals` — 19.1x.** slate still pays a per-statement bookkeeping cost at module scope that a
  tree of function calls does not (documented at length elsewhere in this repo's `CLAUDE.md`); this is
  the one existing finding the qjs column corroborates rather than a new one.
- **`strwalk` — 3.7x.** The quadratic character-walk benchmark, deliberately the one program Lua is
  not a yardstick for either — QuickJS decodes UTF-16 code units in O(1), so this is the same
  underlying gap `strings` shows, at a much smaller absolute scale (10.3 ms vs 2.8 ms).

**Furthest ahead** (`/qjs` ratio lowest — slate fastest relative to QuickJS, i.e. slate *beats*
QuickJS):

- **`mapset` — 0.1x.** QuickJS took **3370.8 ms** against slate's 252.9 ms, over ten times slower than
  every other runtime measured on this program including CPython (106.2 ms). Confirmed independently
  outside the harness — three direct `qjs mapset.js` runs on an idle box (91% idle, `pgrep -x java`
  empty) came back 3.31 s, 3.38 s and 3.39 s, so this is not a fluke of the harness or the machine.
  `mapset.js` inserts and overwrites 2,000,000 times into a `Map`/`Set` holding only 1,000 distinct
  keys (`m.set(i % 1000, i)`); QuickJS-ng's `Map`/`Set` implementation is evidently far more expensive
  under sustained overwrite churn than V8's (`node --jitless`: 88.6 ms) or slate's own hash table.
- **`sorting` — 0.4x.** QuickJS is the slowest of all five runtimes on this program (1169.1 ms against
  slate's 525.1 ms), slower even than `node --jitless` (813.0 ms).
- **`loops` — 0.5x**, and **`nested` — 0.9x** close behind. Two more where slate, despite being 2.5x
  and 3.8x off Lua respectively, comes out ahead of or level with QuickJS.

## Method

Idle check before the run: `top -l 2 -n 0 -s 1 | grep "CPU usage"` read 86.70% idle, `pgrep -x java`
and `pgrep -x perl` both empty. `bench/run.sh -n 5 ./slate` (default program list, all 23) under
`caffeinate -dimsu`. Every program's `qjs` output was diffed against its `node` output beforehand and
matched exactly, so the timing differences above are not the two engines answering different things.

## What this closes

Adds `qjs` as a permanent fifth runtime in `bench/run.sh` and `bench/README.md`'s current-position
table, alongside the existing three yardsticks. No shim was needed and no program was excluded from
the mean.
