# 2026-09-23 — sysl 0.0.128: thin LTO in the manifest, and a profile-guided release build

**A compiler pickup, and the two levers it adds are worth a fifth of the interpreter together.** On
dev `5240032`, same compiler on every side, alternating best-of-9:

| build | geomean vs control | binary | build time |
|---|---|---|---|
| (a) control: `-O2`, no `lto` | — | 5,914,776 bytes | 111 s |
| (b) `-O2`, `lto = "thin"` (the manifest, `sysl build .`) | **−6.56%** | 6,037,304 bytes | 127 s |
| (c) (b) plus a profile, `bench/pgo.sh` | **−22.22%** | 5,811,064 bytes | 251 s (all three steps) |

**New position, `bench/run.sh -n 5` on (c): 2.2x Lua / 1.6x node --jitless / 1.1x CPython / 1.3x
qjs**, from 3.0x / 2.3x / 1.6x / 1.9x at the 0.0.126 pickup (other items have landed since, so that
is not this item's delta alone — the tables below are). `check.sh` answers unchanged on (c) for all
four runtimes.

Nothing under `dev/` moved. The diff is `package.hocon` (the `sysl` floor to 0.0.128 and
`lto = "thin"`), the two `SYSL_VERSION` workflow pins, and `bench/pgo.sh` with its `.gitignore` line.

## What 0.0.128 adds

- **`lto` in the manifest** (`thin` or `full`; `--lto` on the command line beats it). sysl already
  lowers the whole program into one LLVM module, so `-O2` inlines across slate's own code; what it
  could not reach is the C the packages vendor and the shims beside the standard library. Thin LTO
  is what lets a call over that seam be inlined — and 0.0.128 also builds the standard module at the
  build's level and *inside* the LTO, which is the other half of the same seam.
- **`--profile-generate <dir>` / `--profile-use <file>`**, reaching every clang the build drives.
  Deliberately not a manifest key: a profile is one machine's measurement.

**The floor moves because of the key, not the release.** An older compiler ignores an unknown
top-level member rather than refusing it, so building this manifest with 0.0.127 would silently
drop the LTO — `optimization`'s case at 0.0.122 exactly.

## The control

**Every program is faster**, and the profile is worth about three times what the link alone is. The
largest movers are the programs whose time is the dispatch loop itself — `fib`, `dispatch`, `reals`,
`arith` — which is what a profile is for: `run_frames` is one enormous `match`, and the optimizer
laying it out around the arms that are actually taken, rather than around their order in the source,
is exactly the thing no static reading can do. `strings` barely moves because its time is inside
`Buf` growth and the allocator, which were already hot and straight-line.

**The training set is the benchmark set**, so this is the best case for these twenty-three programs;
a program with a different mix will see less. What argues it is not overfitted is that the gain is
broad (every one of the twenty-three, nothing under −3%) and follows the machine's hot path rather
than any one program — and that sysl measured −12.5% for the profile on top of thin LTO on its own
older tree, the same order.

## The recipe — `bench/pgo.sh`

```
bench/pgo.sh [out-dir]
```

It builds `sysl build . --lto thin --profile-generate <out>/raw -o <out>/slate-instrumented`, runs
the instrumented binary once over every `bench/*.sl`, merges with the `llvm-profdata` the compiler
names (`clang -print-prog-name=llvm-profdata`, Xcode's on this machine — Homebrew's on the `PATH`
is a different LLVM and refuses the raw format), rebuilds with `--profile-use <out>/slate.profdata`
into `<out>/slate`, and prints that path. The out directory defaults to `pgo/` at the root, which is
ignored, and is emptied first so a stale counter file can never be merged in. The instrumented
binary is 10,243,152 bytes; the profile-guided one is **smaller than either plain build**, cold code
being moved out of the hot path's way.

**The release tarball is built with `bench/pgo.sh` from now on**, and the binary it prints is the one
staged. It costs about two extra minutes over a plain build. The Linux runners keep `sysl build .`
(thin LTO from the manifest, no profile) for now: a profile is per machine, and training one on a
runner is a workflow change of its own.

## Gate

The three shapes ran on the merged tree, every one of them built with the manifest's thin LTO.

## What this closes and what stays open

**No shortlist line is struck**; this is a compiler pickup like 0.0.122–0.0.126. It moves the floor
under everything left on the list — the dispatch head in particular is now laid out by a profile, so
**a sampled profile taken before the next head item is priced will read differently from profile
5's**, and a measurement of any future item should build both sides the same way (both plain `sysl
build .`, which is now thin LTO) rather than comparing a PGO binary against a plain one.
