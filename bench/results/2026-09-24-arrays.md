# 2026-09-24 — AN ARRAY LOOP'S THREE READS ARE ANSWERED IN PLACE: `xs.length`, `xs[i]` AND `for x in xs`

`arrays.sl` builds an array of 500,000 by `push`, then reads it back ten times by index and ten times
by `for`. On dev `f6a68f7`'s PGO build it took **116–126 ms: 1.5x PHP, 1.2x Lua**. It now takes
**89 ms, −28.6%: 1.0x PHP and 0.9x Lua** — faster than Lua, and level with PHP's packed vector.

Control `f6a68f7` (dev); branch `arrays`. Both sides built with `bench/pgo.sh`.

## What the profile said

The program split three ways on the control, best of five each (each program still builds its array):

| part | ms |
|---|---|
| the build alone (`push` ×500,000) | 9.8 |
| the build + ten `by_index` walks | 87.3 |
| the build + ten `by_walk` walks | 38.7 |

So `push` was never the item — its charge is capacity-based already, and the whole build is 10 ms — and
the index loop was three quarters of the program. `--features profile` gave **79,500,478 instructions**:

| per turn | control | branch |
|---|---|---|
| `while i < xs.length` | `Tick`, `LoadSlot2`, `GetField`, `LessJumpIfFalse` | the same four |
| `total = total + xs[i]` | `LoadSlot2`, `LoadSlot`, `GetIndex`, `AddStoreSlot` | `LoadSlot2`, **`LoadSlotIndex`**, `AddStoreSlot` |
| `i = i + 1` + back edge | `SlotIntAddStoreJump` | the same |
| **`by_index`, a turn** | **9** | **8** |
| `for v in xs` | `Tick`, `IterNext`, `DeclareSlot` | `Tick`, **`IterNextSlot`** |
| `total = total + v` + back edge | `LoadSlot2`, `AddStoreSlot`, `Jump` | the same |
| **`by_walk`, a turn** | **6** | **5** |

**Instructions 79.5M → 69.5M.** But the count was the smaller half of it. The expensive instruction was
`GetField` for `xs.length`: an array is not an object, so `read_field_site` handed it to
`read_field_of_kind`, which looked the NAME up in the kind's property table (`method_kind` + a string
lookup), found `NLen`, and called it through the builtin dispatch with a standing window
(`standing_property`: `current()`, two profiler reads, the table call, `do_len`'s argument-count check,
its kind match, a truncate). Five million times, for a number the array carries.

## The change

Three reads, each with the general path behind it unchanged:

- **`.length` off an array, a string or bytes is answered in `read_field_site`** — `Array(a) ->
  Int(a.items.len())`, `Str(p) -> Int(str_count(p))`, `Bytes(b) -> Int(b.data.len())`, `do_len`'s
  answers arm for arm. `Unit.length_hash` is `"length"` hashed once, so every other name read off a
  builtin kind pays one integer comparison before the ordinary path; a hash hit is confirmed by the
  string. A range (whose length can fault) and every other name keep `read_field_of_kind`.
- **`LoadSlot(i); GetIndex` is `LoadSlotIndex(i)`**, and `GetIndex` itself answers an array at a whole
  number inside it where the two stand (`compose_get_index`, `indexed_in_place`): the element written
  over the container, the key cut off, no `Step` back through `read_at`. `fuse` leaves the load in front
  of the index single rather than pairing it, `slot_rem_at`'s rule, so `total + xs[i]` is
  `LoadSlot2(total, xs); LoadSlotIndex(i)`. Out of range, negative, a real, a string, a range slice, a
  string or bytes receiver: `read_at`, unchanged, with the `GetIndex`'s span.
- **`IterNext(to); DeclareSlot(i)` is `IterNextSlot(to, i)`**: the element goes straight into the loop's
  cell, never pushed, `keepable` still asked with the `DeclareSlot`'s span. The step is now
  `iter_next_on` in `run_compose.sysl` — an array and a range inline, every other kind in
  `iter_next_other` — which both walk instructions call, taking 60 lines out of `run_frames.sysl`. A head
  that takes the element apart keeps `IterNext`.

Found on the way and fixed: **the JavaScript back end refused a `for` over something unwalkable in
different words** — "an integer is not something to walk over" and "a range with an open end cannot be
walked" where the interpreter says "`for` walks an array, bytes, a string, a range, a generator, a set
or a map, and this is an integer" and "`for` needs a range with both ends, since one left out would
never finish". `js_rt_dispatch.sysl`'s `iter` now says the interpreter's sentences.

`fib` and `arith`, which run none of the three reads, are the controls: `fib` moved −0.5%, `arith`

all it does with the new paths is two `ys[0]`-shaped reads a turn — read it as layout and a busy box.
`strindex`/`startup`/`strings` are 3–9 ms programs and their ±3–10% is noise at that size. The
geometric mean without `sorting` is −2.58%.

## The witnesses

- **`tests_indexwalk.sysl`**: `A_LENGTH_READ_OFF_AN_ARRAY_A_STRING_OR_BYTES_CALLS_NO_BUILTIN` (three
  hundred reads of each charge `length` nothing; a range beside them in the same program charges it
  300 — the control that could disagree); under `--features profile`, `LoadSlotIndex` = 100 and
  `GetIndex` = 0 for the index loop with `xs[i + 0]` as the control (0 and 100), `IterNextSlot` = 101
  with one `DeclareSlot` left for the walk and a `for [a, b]` head as the control (`IterNext` = 3), and
  a turn costs **8** and **5** instructions, measured as the difference between 150 and 100 turns.
- **`tests_profile.sysl`**: `A_PROPERTY_READ_UNDER_SLATE_PROFILE_COUNTS_AS_ITS_BUILTIN` reads a
  RANGE's `length` now, an array's no longer being a builtin call.
- **`tests/lang/indexwalk.sl`**, both back ends: an array at a local index; out of range at 3, −1 and on
  an empty array, word for word; a real, a string and a range as the index; a string with a
  multi-byte character and bytes as the receiver; `.length` off an array, `"日本語"`, `toBytes("日本")`,
  a range and an open range; another name off an array; `for` over an array, empty, two ranges, a
  string, bytes, a set, a map and a generator; a destructuring head; `break` out of and nesting of
  walks; and the two refusals the back ends now share.

`SetIndex` and `push` were not changed: the build is 10 ms of the 89.
